# Text rendering in `div.exe`

Which texts the game draws with which fonts, its GDI font path (`use8bitfont 0`), the text table and text fields. Font objects, glyphs, drawing, layout and colors (both paths): `glyph-layout.md`. What the mod does: `fonts-mod.md`. Bitmap font file layout and families: `file-formats.md`. Addresses: verified 1.0062A `div.exe` (`game-version.md`).

## Which texts use which path

`use8bitfont` in `config.lcl` (or the mod's font mode, `fonts-mod.md`) switches **all** game text at once: with `1` the game opens all 61 `fonts/*.fnt` files at startup and no GDI font; with `0` it opens **no** `.fnt` file and instead creates **one GDI font per bitmap font** – the same list of 61 in the same order (fixed table in `div.exe`), every one as face **"SimSun"** (a Chinese system font – the mode was evidently made for the Chinese version), weight 600, `ANSI_CHARSET`, height per family. Measured with the font log (`LogLevel=debug`) in DE and EN, identical in both.

## Path

- The font class (`CDivinityFont`, source `.\font\Font.cpp` per assert strings) has two GDI constructors: one takes face name, height, weight, italic and underline and calls `CreateFontA` (around `0x494330`); the other takes a full `LOGFONTA` and calls `CreateFontIndirectA` (around `0x493E20`; the 61 game fonts come through here, return address `0x493E39`). A third function (around `0x499040`) lists installed fonts with `EnumFontFamiliesExA`.
- The font descriptors carry two face names (tried in order, then any font of the character set via `EnumFontFamiliesExA`), height, weight 600 and a color; the GUI code (`.\BMGUI\Bmgui.cpp`) can read an optional `fontlist.txt` (not present in the Steam installation). Without it the faces are "SimSun". A list of the enumerated fonts can be written to `ttfonts.lst`.
- `CreateFontA("Arial Bold", 18, …)` (around `0x5A84D1`) is the only face name in `div.exe`; it was not called up to character creation. On Windows that request gives **Arial** – there is no family named "Arial Bold".
- **Timing:** all 61 fonts are created within the first ~200 ms of the process, long before the game window exists – a hook must be in place when the mod is loaded (the deferred start is too late).
- The font is selected into a **memory DC** (`CreateCompatibleDC`, based on the screen DC from `GetDC(NULL)`). Nothing is drawn with `TextOut`/`ExtTextOut`, and **no GDI call touches a DirectDraw surface** – `div.exe` does not import DirectDraw at all.
- Each character is rasterized once, on first use, with `GetGlyphOutlineA` in 8-bit gray mode (`GGO_GRAY8_BITMAP`, 65 levels). The gray levels are mapped through a 65-entry color ramp (the family's color) to 16-bit pixels (RGB565 or RGB555 depending on a game global that matches the renderer's 565 flag) and converted into the game's own sprite format. The result is cached per byte value (table of 256 entries); drawing is then done by the game's 2D sprite blitter into the back buffer (`renderer-d3d6.md`).
- Metrics: the space character is measured at creation (`GetGlyphOutlineA` with `GGO_METRICS`); each cached glyph keeps its black-box size, origin and advance.
- **Font object and glyph:** full layout in `glyph-layout.md`. GDI specifics: the GDI part at `+0x00` holds the `HFONT`, the memory DC at `+0x08` and a `MAT2` at `+0x0C`; `+0x0C` of the font object is the game's own `lfHeight` (not the one the hook passes to GDI).
- **Glyph creation** (around `0x493F80`, `__thiscall`, character as argument): returns nothing for the space and for a cached glyph; otherwise asks `GetGlyphOutlineA` for the buffer size and **creates no glyph if the size is 0 or the call fails** – the table entry stays null, exactly like a character missing from a `.fnt`.
- **"Has glyph" check** (around `0x4939F0`, `__thiscall`, character and a "create" flag): true for the space or a cached glyph; for a GDI font with the flag set it creates the glyph first. Its only caller is the character handler of the text field (below).
- **Pair spacing** (around `0x494670`, `__thiscall`, previous and next character, returns the distance in pixels; cached per pair in a 256×256 byte table, `0xFF` = not computed): the game places the next glyph at the previous glyph's advance + origin x and slides it left one pixel at a time until its pixels would overlap the previous glyph's (tested at the same height and one pixel up and down), then takes the last free position – so neighbors may **touch**. The overlap test misses the glyphs' bottom row, so feet can even be covered (Tahoma Bold "Li": the "i" stands on the foot of the "L" and the word reads "li"). Exceptions: after a space the space width; quotes and underscore are not slid. The bitmap fonts are drawn for this (no feet, dark anti-aliased edges); with a Windows font crisp shapes touch – in Tahoma Bold 12 px the period after "1" lands right of its foot and both read as one line ("7147" instead of "71.47"). The period is drawn; its pixels merge. The value returned when nothing touches, advance + origin x, counts the left bearing twice: glyphs are drawn at pen + origin x (draw function around `0x4944E0`), so the font's own spacing is the advance alone.

## Text table (localized texts)

- The game loads `localizations\<language>\text.cmp` (or `localizations\text.cmp` when settings `+0x124` is 0) at startup into a global table object (`0x744784`) with its text loader (around `0x505100`, `__thiscall` on the table, one argument: the file name; it frees an earlier load first). File layout: `file-formats.md`.
- Table: `+0x00` pointer to the section pointers, `+0x04` section count. Section (`0x0C` bytes): `+0x00` type, `+0x04` pointer to the entry pointers, `+0x08` entry count. Entry (`0x1C` bytes): `+0x00` text (own allocation, NUL-terminated), `+0x04` second text, `+0x08`/`+0x0C` the two texts with escape sequences `\n \r \t \v` resolved (null if a text has none), `+0x10` id, `+0x14`/`+0x18` the two lengths.

## Text fields

- The save dialog's name field handles keys in two places (text field class, vtable `0x60E02C`): a **key handler** (around `0x4633B0`, slot `+0x30`, virtual keys 0x08–0x2E: Backspace deletes the character before the cursor, Delete, arrows, Home/End, Enter, Esc), which runs when the key is **released** (`input.md`), and a **character handler** (around `0x4632E0`, slot `+0x2C`, `WM_CHAR`), which inserts the character if the font has a glyph for it ("has glyph" check above) and, in name fields, rejects `/ \ ? $ " ! : ; . , < > | * %`.
- Backspace sends a key-down, a `WM_CHAR` 0x08 (insert attempt) and on release the key-up (deletes). The bitmap fonts have no glyphs below 0x20 (checked in all 61 `.fnt` files), so 0x08 is never inserted. A Windows font returns its "missing character" box for 0x08, so the box is inserted and – for a single press – deleted again on release; while the key is held, Windows repeats the key-down and the `WM_CHAR` but nothing deletes, so boxes pile up. Holding Backspace deletes one character only in the original game; `[Features] KeyRepeat` makes Backspace, Delete and the arrows act on press and repeat (`input.md`).

## Consequences

- **All or nothing:** because `use8bitfont` switches all 61 fonts at once, the font mode turns every family into the chain's face. The per-family faces (`fonts-mod.md`) need the per-family font chain and, for the styles, the target text renderer – an own glyph table per font (`glyph-layout.md`) gives both per font without the GDI path.
- **Code page:** the character is passed to `GetGlyphOutlineA` as a *signed* `char`, so bytes ≥ 0x80 (umlauts, accents, Cyrillic) arrive sign-extended. German umlauts and ß of the main-menu hint arrive as the correct characters (font log). The game asks for `ANSI_CHARSET` (0), so GDI maps the bytes through code page 1252. Measured in the Russian version (1.0061, `use8bitfont 0` set by hand, `game-version.md`): the 1251 bytes come out as Latin-1 letters ("ÍÎÂÀß ÈÃÐÀ"). **Setting `lfCharSet = RUSSIAN_CHARSET` (204) in the font hook is enough** – GDI then maps the same bytes through code page 1251 and the main menu shows correct Cyrillic in the chain's face (then Tahoma Bold). The hook does this via `[Fonts] Charset` (`auto` = 1251 for the Russian EXE hash, otherwise the game's charset; `1252`/`1251` force it). The font mode does not run on 1.0061 (best effort, no RE on that EXE), so the Russian version keeps its Cyrillic bitmap fonts unless `use8bitfont 0` is set by hand.
- **Proton:** SimSun is a Windows font; under Proton the game's request is substituted by Wine – one more reason for the hook. Proton ships its own "Tahoma Bold" as `C:\windows\Fonts\tahomabd.ttf` (a different design, not used by the mod), and the bundled faces load through `AddFontResourceExW` (`FR_PRIVATE`) there too (T1.24-D). Wine's GDI picks other heights for the same capital height (e.g. `fontbig36` GDI height 43 against 46 on Windows – the renderer measures per platform, so capital heights match), and its synthetic bold at weight 600 is clearly narrower and thinner than Windows' – the reason for own rasterizing (`docs/decisions.md`, plan B).
- **Overlay:** the game offers no GDI-on-surface path to reuse; the overlay's text approach is decided in `overlay.md`.
