# The mod's fonts

What the mod changes in the game's text: glyph renderer, shared style renderer, colors, short labels, font hook, font mode and the faces per family. Game side: `text-rendering.md`, `glyph-layout.md`; how GDI rasterizes (repeated by the own rasterizer): `gdi-raster.md`. Addresses: verified 1.0062A `div.exe` (`game-version.md`).

## Glyph renderer (`[Fonts] Renderer=glyphs`, default)

- **Glyph renderer (`src/fonts/glyphtable.cpp`, `families.cpp`; `[Fonts] Renderer=glyphs`, default):** hooks the font file loader (around `0x494440`, `__thiscall` on the font object with the file path, signature of its first 48 bytes, fallback RVA `0x94440`). After the original has loaded a file it maps the stem to its family (interface `font{n,gra,red,b,go,or,yel,gr}1–5`, books `fontblack*`/`paper_*`, menu `fontbig24*`/`fontbig36*`, dialog `dialog_*`, diary title `diary_head_*`), decodes the original capitals A–Z from memory (the loaded sprites carry absolute row pointers), measures the capital H and – for the styled families – profile, edge factors and shine, rasterizes the family face at the smallest GDI height whose H reaches the original's (cached per height), puts its H top where the original's is, paints every glyph the original has (ramp in the measured color table's text/edge colors; menu: shine ×2 plus texture; diary title: measured edges), blends partial pixels into the edge tone and replaces the table entry. The menu fonts' arrows in `[`/`]` become own triangles (`fonts::PaintArrow`, `src/text/symbols.cpp`): filling the original's inked box, painted with the color profile and edge shading measured from the original arrow itself (no shine or texture – the originals are smooth), moved down with the letters (`TopFit=lower`); `[Family.Menu] Arrows=original` keeps the original glyphs. A character the face lacks keeps its original glyph (Almendra SC: `… † ‡ ‰ ™ š ž ƒ`; Fondamento and Uncial Antiqua: `ƒ`). Space width from the face; line height per family (`LineHeight` percent or `auto` = at least the original and the ink extent of `bdfhklgjpqyß` + 1: books 12 → 18 and 17 → 25). The pair spacing hook spaces these fonts by their own advance. Rasterizing: GDI, grayscale only (`ANTIALIASED_QUALITY`, `GGO_GRAY8_BITMAP` – never ClearType, independent of the player's smoothing settings). Measured (DE + EN, 1920×1080): all 61 fonts, 7261 glyphs in ~750 ms at startup; every glyph the originals have is replaced (130–131 per interface/books/dialog font, 43 letters plus 2 arrows per menu font) except one slot per diary-title font that Almendra SC lacks. Russian edition: not installed, the Cyrillic bitmap fonts stay.
- **Shared style renderer (`src/text/`):** `style.*` holds the measurements (capital H top and height, color profile in 16 steps over the capital height, edge factors per side and distance, brightness across horizontal and vertical stroke runs in five steps, texture strength) and the painters (game ramp; profile with optional contour, fixed gloss, measured edges, shine across the strokes and own value noise) plus the conversion to the game's sprite pixels (partial coverage blended into the family's edge tone, never 0); `gdiface.*` rasterizes a face like the font mode (positive cell height, weight, 65 gray levels; per glyph as a padded coverage mask, smallest height for a given capital H). `ddmod_fontpreview --scene` draws its sheets with the same code (unchanged output); the glyph tables use it from R2 on (`docs/decisions.md`).

## Text colors (`[Fonts] Colors`)

- **The mod (`src/fonts/fontcolors.cpp`, `[Fonts] Colors`):** `original` (default) hooks the descriptor function (`glyph-layout.md`, Colors; signature of its first 64 bytes – the first 48 alone also match the `.fnt` loader at `0x496750`; fallback RVA `0x96670`) and replaces the two colors of the n-th call by the colors of the n-th bitmap font, only while each call matches the expected height and game colors (so a `fontlist.txt` or another EXE keeps the game's colors). The table holds the measured colors (interior mode; mean for the textured families) and passes the smallest bytes that survive the rounded conversion unchanged. `game` leaves the game's colors.

## Short menu labels (`[Fonts] ShortLabels`)

- **Menu labels in the mod's menu face** are about 1.2× as wide as in the bitmap font (`ddmod_fontpreview --labels`: DE/EN/FR); the options pages leave about 500 px (at 2560×1440) between a label's start and the left arrow. Only DE "HINTERGRUNDGERÄUSCHE" (sound page, 568 px, original 473) runs over it; DE "SCHWIERIGKEITSGRAD" and FR "NIVEAU DE DIFFICULTE" (game page) keep about 29 px; "NEBEL GESCHWINDIGKEIT"/"FOG UPDATE SPEED"/FR "RAPIDITE MISE A JOUR BROUILLARD" (fog speed) appear on no page. The mod shortens the one label in place after loading (`src/features/shortlabels.cpp`, `[Fonts] ShortLabels`): "HINTERGRUND" – a workaround until the menus get an own layout.

## Font hook (`src/fonts/fonthook.cpp`, v0.01)

- Hooks `CreateFontIndirectA` and `CreateFontA` (gdi32 exports) in `DllMain` – the only point early enough. Calls from inside `div.exe` get the face of the font chain (`[Fonts] Chain`: the bundled DejaVu Sans Condensed Bold, `overlay.md`) and the height scaled by `[Fonts] GameFontSize` (percent); weight and the game's colors stay; the charset follows `[Fonts] Charset` (`text-rendering.md`, Consequences). Calls from other modules are passed through. `[Features] FontHook=0` switches it off together with the font mode below.
- The chain is resolved on the first hooked call (game thread, not under the loader lock) and logged ("Font chain: using …"). Measured (DE + EN, Windows): main menu and character creation are drawn in the chain's face instead of SimSun.
- **Control characters:** the hook also takes `GetGlyphOutlineA`; for calls from `div.exe` with a character byte below 0x20 it returns `GDI_ERROR`, so the game creates no glyph – as with the bitmap fonts – and text fields no longer insert Backspace as a box. With `LogLevel=debug` the same detour feeds the font log ("GDI glyphs of font …").
- **`GameFontSize`** works: glyphs are rasterized from the scaled `HFONT` (150 % gives clearly larger text). The game's layout does not follow because the hook scales only the `HFONT`: the font object's line height `+0x0C`, which the layouts use as line pitch (`glyph-layout.md`, Layout), keeps the game's value, so larger text overlaps or gets cut ("…"). The vertical origin uses the same unscaled height.
- **Spacing (`src/fonts/spacing.cpp`):** `[Fonts] Spacing` hooks the pair spacing function (signature of its first 36 bytes, unique; fallback RVA `0x94670`) for GDI fonts only: `font` (default) returns the previous glyph's own advance – the font's designed spacing, no sliding; `game` leaves the game's value; `gap` adds one pixel where the game slid a character closer than its no-touch distance. Bitmap fonts always keep the game's spacing. Measured (DE + EN: load dialog, letter, two books, NPC dialog): `font` shows every period ("71.47 GB", "1.", "2.") and "Lieber" correctly, about as wide as the game's spacing – same line breaks or one word moved, all save names fit; `gap` still hides "2." in the dialog and the foot in "Li" (bottom row, `text-rendering.md` pair spacing).

## Font mode (`src/fonts/fontmode.cpp`, v0.01)

`FontHook=1` also switches the game to the GDI path in memory, so `config.lcl` keeps `use8bitfont 1` (as shipped).

- **Reader:** the settings byte `+0x120` (`config-files.md`) is read in exactly one place for the choice of fonts: the font setup function (`0x45BF90`, `__thiscall`, no stack arguments; source `.\BMGUI\Bmgui.cpp`). It first tries to open `fontlist.txt`; with or without that file it reads the byte once and then either loads the 61 `.fnt` files or creates the 61 GDI fonts. The only other reader is the `config.div` writer (below).
- **Timing:** the startup function calls the font setup once (call at `0x40DBD5`), on the main thread and before the game window exists. It reads the byte through the global settings pointer (`0x0065B3D0`), so the configuration is parsed by then. The mod is loaded earlier (ASI loader, `DllMain`).
- **Hook:** a MinHook on the font setup sets the byte to 0 before the original runs and restores the configured value afterwards; the log says "use8bitfont forced to 0 (was 1)". If the settings pointer is still null the call is passed through unchanged.
- **Signature:** the first 34 bytes of the function (`fontmode.h`), ending with `A1 <settings pointer>` and the compare of `+0x120` with 0 – unique in `div.exe`; the settings pointer address is read from the `A1` operand. Fallback RVA `0x5BF90` for the verified build only.
- **Write-back:** on exit the game writes `config.div` (`0x48C6F0`), only keys found in a set at settings `+0x154` – in practice the keys that were in `config.div` (`config-files.md`); `use8bitfont` lives in `config.lcl` and does not end up there. Because the hook restores the byte, even a `use8bitfont` line in `config.div` would be written back with the user's value.
- Measured (DE + EN, Windows): with `use8bitfont 1` in `config.lcl` and `FontHook=1` no `.fnt` file is opened, the main menu is drawn in the chain's face; with `FontHook=0` the original bitmap fonts.

## Faces per family (human's choice, `docs/decisions.md`)

| Family | Face (OFL) | GDI height for the original's capitals (H, or median over A–Z) | Style |
|---|---|---|---|
| Menu capitals (`fontbig36*` / `fontbig24*`) | Uncial Antiqua, weight 600 | median: 46 / 33 (its H reaches 6 px above the other capitals; ink kept below the line top, font 8 / 5 px lower) | measured color, rounding across the strokes ×2 plus own texture noise (`shine200`, `tex`) |
| Diary title (`diary_head_*`) | Almendra SC, weight 600 | median: 50 / 40 / 33 (its H reaches 5 px higher; accents moved close, font 6 / 5 / 4 px lower – `TopFit=lower`; Â/Ê/Î/Ô/Û set the amount) | measured color profile and light rim (`measured`) |
| Interface (`font*1–5`) | Marcellus SC, weight 600 | 17 / 16 / 14 / 12 for sizes 1–4 | game ramp |
| Books/letters (`fontblack1/2`) | Fondamento, weight 400 | 21 / 29 | game ramp |
| Dialog | DejaVu Sans Condensed Bold (Bitstream Vera license; a real bold cut, weight 700) | game height | game ramp |

- **Height:** the game passes one cell height per family and every face fills it differently, so each family needs its own height (factor) to match the original's capital height.
- **Line pitch of books and letters is 12 px** (measured on the "Windgeflüster" letter); the bitmap original fills it with almost no ascenders or descenders. Any vector face at the original's capital height touches the neighboring lines ("g" into "fl"); at the largest non-touching size it comes out smaller than the original (GDI height 12–16). The human accepted the touching lines; the pitch is `fontblack1`'s line height `+0x0C`, so an own glyph table can widen it and the page break follows (`glyph-layout.md`, T1.13-W).
- **Dialog face:** the original dialog bitmap font is closest to Tahoma Bold (`file-formats.md`), but Tahoma is a Microsoft system font – not shippable, and under Proton Wine's look-alike drawn by Wine's GDI comes out clearly thinner and wider spaced (T1.26-D). DejaVu Sans Condensed Bold through the own rasterizer is pixel-identical on Windows and the Deck, a little heavier and larger than the original (comparison `C:\dev\screenshots\deck\t126\cmp\11-dialog-faces.png`).
- **Licenses:** the four OFL faces ship with `OFL.txt`, DejaVu with `LICENSE-DejaVu.txt`. Probable source faces of the bitmap fonts: dialog Tahoma/Verdana Bold, interface Lithos, handwriting Ondine (commercial), diary Vinque (Typodermic; its free desktop license excludes games and software that include the font), menu capitals unknown Lombardic (free Lombardic faces do not exist; Goudy Text Lombardic and Tarisel are commercial).
- **Comparison sheets** (outside the repo, `C:\dev\screenshots\fonts\`): `candidates\Schriftvergleich.pdf` (round 1) to `candidates5\Schriftvergleich-Runde5.pdf`, `candidates6\Menue-Glanz.pdf` (gloss); specs and fonts: `--scene` (`docs/dev/workflow.md`), downloads in `environment.md`.
